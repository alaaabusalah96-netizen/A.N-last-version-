# الخط المرجعي للأمان والحماية (Security Baseline)

## 1. إدارة الهوية والمصادقة المستقلة (Self-Sovereign Identity)
- النظام يمتلك بالكامل دورة حياة الهوية والمصادقة دون الاعتماد على أي خدمات خارجية طرف ثالث أو سحابة مغلقة (مثل Firebase).
- خوارزمية تشفير كلمات المرور المعتمدة: **Argon2id** (أو ما يكافئها من خوارزميات التجزئة المتكيفة والمقاومة لهجمات GPU مثل bcrypt بمعامل كلفة مرتفع).
- يُمنع تمامًا حفظ كلمات المرور أو أجزاء منها بنص صريح (Plain Text).

## 2. إدارة الجلسات والرموز (Session & Token Management)
- الاعتماد على جلسات آمنة مشفرة أو رموز مميزة (Cryptographically Secure Tokens).
- استخدام كوكيز آمنة (`HttpOnly`, `Secure`, `SameSite=Strict/Lax`) لمنع هجمات سرقة الجلسات وسرقة الرموز عبر XSS.
- تحديد أوقات انتهاء صلاحية واضحة للجلسات مع دعم الإلغاء الفوري (Revocation) عند تسجيل الخروج أو تغيير كلمة المرور.

## 3. حظر الحسابات وكلمات المرور الافتراضية (Zero Default Credentials)
- يُحظر تضمين أي حسابات افتراضية (Default Accounts) أو كلمات مرور صلبة (Hardcoded Passwords) مثل `admin/admin` في شجرة الكود أو قواعد البيانات.
- يتم تهيئة حساب المدير الأول للنظام أثناء عملية التثبيت (Initial Bootstrapping) عبر معالج آمن أو متغيرات بيئة مؤقتة تتطلب تغييرًا فوريًا.

## 4. إدارة الأسرار والمتغيرات البيئية (Secrets Management)
- تُحفظ كافة مفاتيح التشفير، أسرار الجلسات، بيانات الاتصال بقواعد البيانات، وبيانات الربط في متغيرات البيئة (`Environment Variables`) فقط.
- يُمنع نهائيًا كتابة أي سر أو رمز سري داخل ملفات الكود أو التوثيق أو حفظه في مستودع Git.

## 5. الحماية ضد إساءة الاستخدام والفيضان (Rate Limiting & Abuse Prevention)
- تطبيق حدود لمعدل الطلبات (Rate Limiting) على كافة نقاط النهاية العامة ونقاط المصادقة لتفادي هجمات التخمين (Brute Force) وهجمات حجب الخدمة (DoS).
- تفعيل آليات قفل الحساب المؤقت بعد عدد محدد من المحاولات الفاشلة لتسجيل الدخول.

## 6. العزل الصارم لسياق المستأجرين (Tenant Isolation Enforcement)
- تطبيق التحقق الإجباري من سياق المستأجر (`Tenant Context`) عند كل عملية أو استعلام.
- حظر أي استعلام عام يتجاهل شرط `tenant_id` إلا لعمليات المشرف العام للمنصة ذات الصلاحيات المخصصة والموثقة.
- منع هجمات حقن المعرفات (IDOR) عبر التحقق من تبعية الكائن للمستأجر الحالي قبل أي قراءة أو تعديل.

## 7. سجل التدقيق والحوكمة (Audit Trail)
- تسجيل تدقيق شامل وغير قابل للتعديل (Append-Only Audit Log) لكافة العمليات الحساسة:
  - عمليات تسجيل الدخول والخروج ومحاولات الدخول الفاشلة.
  - إنشاء وتعديل وحذف الحسابات والصلاحيات.
  - العمليات المالية، القيود المحاسبية، وتعديل إعدادات الشركات.
- يتضمن سجل التدقيق: معرف المستخدم، معرف المستأجر، التوقيت بدقة، عنوان IP، نوع العملية، والقيم السابقة والجديدة.
