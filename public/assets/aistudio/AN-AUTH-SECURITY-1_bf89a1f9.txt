## Goal
1) CSRF protection for cookie-authenticated unsafe methods
2) Login failure rate limiting (DB-backed table preferred; memory only if DB down + documented)
3) Persistent audit_logs for auth and company admin events
4) Session hardening: revoke all on password change path (hook), reject inactive users
5) Readiness remains strict when DB required
6) Tests with PASS/FAIL/BLOCKED — no fake PASS

audit_logs:
- id UUID PK
- actor_user_id UUID null
- company_id UUID null
- action VARCHAR(150) NOT NULL
- entity_type, entity_id optional
- ip_address, metadata JSONB default '{}'
- created_at

login_rate_events (or rate_limit_buckets):
- key TEXT (e.g. ip:username)
- window_start TIMESTAMPTZ
- fail_count INT
- primary key (key, window_start) or single row upsert by key
